External API Limits Cheat Sheet for n8n
=======================================

Notes
- Limits change over time by plan, endpoint, and region.
- Values below are practical defaults or commonly observed ceilings. Always verify with current official docs before production hard-coding.
- n8n strategy pattern: Wait + retry with exponential backoff + jitter + idempotency key.

# Service: Notion API
- Typical limit: around 3 requests/second per integration.
- n8n mitigation:
  - Add Wait node between write calls (for example 300-500 ms).
  - Batch updates and avoid unnecessary writes.

# Service: Airtable API
- Typical limit: around 5 requests/second per base.
- n8n mitigation:
  - Use batch create/update operations.
  - Queue writes and throttle per base.

# Service: Slack Web API
- Typical limit: tiered by method; many methods are minute-window based.
- n8n mitigation:
  - Respect Retry-After on 429.
  - Split high-volume posting across time windows.

# Service: Discord API
- Typical limit: route-based with global limits and strict burst control.
- n8n mitigation:
  - Centralize send queue.
  - Use per-route throttling and retry-after.

# Service: Telegram Bot API
- Typical limit: bot-level and chat-level anti-spam limits.
- n8n mitigation:
  - Insert Wait in fan-out messaging flows.
  - Group notifications rather than per-event messages.

# Service: GitHub REST API
- Typical limit: primary hourly limit + secondary abuse detection.
- n8n mitigation:
  - Use conditional requests (ETag) and pagination.
  - Back off aggressively on abuse warnings.

# Service: GitHub GraphQL API
- Typical limit: point-based quota per hour.
- n8n mitigation:
  - Minimize query cost and requested fields.
  - Cache stable metadata.

# Service: GitLab API

Reusable n8n Pattern
- Node chain recommendation:
  - Trigger -> Split In Batches -> HTTP Request/API Node -> IF(status=429/5xx) -> Wait -> Retry loop
- Controls:
  - max retries: 3-7 depending on SLA
  - backoff: exponential (for example 1s, 2s, 4s, 8s) + random jitter
  - idempotency key: required for write operations to avoid duplicates
