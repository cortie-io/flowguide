## 0. 이 보고서를 왜 다시 썼는가 — 모델 선택 결함 발견과 수정

이 결과는 **두 번째로 돌린 버전**이다. 최초 실행(N=330, 1차)에서는 채점 하네스(`eval/run_pilot.py`)의 `call_tier23()` 함수가 `/api/workspace/stream` 요청에 `model` 파라미터를 지정하지 않았는데, 서버 기본값이 `.env`의 `LLM_MODEL=gpt-4o-mini`였다. 그 결과:

- **Tier 1(Raw LLM)**: `call_tier1_raw()`가 명시적으로 `MODEL = "gpt-4o"`를 호출 → 실제 GPT-4o
- **Tier 2/3(H_pre[+H_post])**: model 파라미터 누락 → 서버 기본값으로 폴백 → 실제로는 **GPT-4o-mini**

즉 논문 §2.4가 전제로 삼는 "동일 LLM 엔진 비교"가 실제로는 지켜지지 않고 있었다. 이 사실을 발견한 뒤 `call_tier23()`에 `"model": "openai:gpt-4o"`를 명시적으로 추가해 수정하였고(코드 수준에서 3개 호출 경로 — 의도분류·ctx 전달·생성 — 를 전부 직접 추적해 재검증), 기존 결과를 폐기하고 N=330 전체를 처음부터 재실행하였다. 이 문서는 **수정 후 재실행 결과**만을 다룬다.

이 발견이 왜 중요한지는 **6절(1차 결과와의 비교)**에서 상세히 다룬다 — 결론만 먼저 말하면, 일부 효과(PCR)는 작아졌지만 유지되었고, 일부 결과(WIS 역전)는 완전히 사라졌다.

## 1. 평가 지표 상세 설명

### 1.1 PCR (Parameter Conformance Rate, 파라미터 정합률)

**무엇을 측정하는가**: 생성된 n8n 워크플로우 JSON에서 각 노드의 `parameters` 객체에 등장하는 키(파라미터명)가 n8n 공식 스펙(`n8n_properties_spec.txt`, `reg_validator._VALID_PROPERTIES`, 2,224개 유효 속성명)에 실제로 존재하는 이름인지를 검사한다.

**계산 방법**: `PCR = (유효한 파라미터 키 개수) / (전체 파라미터 키 개수)`. 예를 들어 한 워크플로우에 파라미터가 7개 있고 그중 5개가 스펙에 존재하면 PCR=0.714다.

**PCR_raw vs PCR_final**: Tier 2/3는 동일한 LLM 생성 결과를 공유하지만 채점 방식이 다르다. PCR_raw는 REG(규칙 기반 교정기)가 교정을 적용하기 전의 원본 파라미터 키를, PCR_final은 REG가 제시한 교정(`json_key` 컨텍스트의 correction)을 실제로 적용한 뒤의 키를 채점한다. 프로덕션 백엔드는 교정안을 사용자에게 "제시"만 할 뿐 실행되는 JSON을 자동으로 재작성하지 않으므로, PCR_final은 "만약 교정이 적용되었다면"을 시뮬레이션한 값이다.

**왜 이 지표를 쓰는가**: 사람이나 LLM의 판단 없이 문자열 대조만으로 100% 재현 가능하게 채점할 수 있다(§4.2). "환각"의 가장 흔한 형태(존재하지 않는 파라미터명을 지어내는 것)를 직접적으로 포착한다.

### 1.2 SA (Structural Alignment, 구조 정합도)

**무엇을 측정하는가**: WORKFLOW_BUILD 응답이 §3.5의 출력 통제 스키마가 요구하는 필수 구조 요소를 빠짐없이 갖췄는지를 5개 체크리스트 항목(마크다운 설명 존재, ```json 코드 블록 존재, JSON 파싱 성공, `nodes` 배열 존재·비어있지 않음, `connections` 객체 존재)으로 검사한다.

**계산 방법**: `SA = (통과한 체크 항목 수) / 5`.

**왜 이 지표를 쓰는가**: "후속 파서가 기계적으로 처리 가능한 형태로 응답이 왔는가"라는, 실용적으로 매우 중요하지만 PCR과는 별개인 품질 차원을 포착한다. Raw LLM은 출력 통제 프롬프트가 없으므로 자유 형식으로 응답할 수 있어 SA가 낮게 나올 수 있다.

### 1.3 WIS (Weighted Issue Score, 가중 이슈 점수)

**무엇을 측정하는가**: `semantic_validator.py`(규칙 기반 검증기)를 응답 텍스트에 직접 적용해, 탐지된 위반 사항에 심각도별 가중치(ERROR=3, WARNING=2, INFO=1)를 곱한 합. **낮을수록 우수**하다.

**중요한 설계 원칙**: 이 검증기는 Tier1·Tier3 양쪽 텍스트에 **동일한 함수(`score_wis()`)를 동일하게 적용**한다 — 즉 "Tier3 생성 시 프로덕션이 실제로 사용한 검증 결과"를 재사용하는 것이 아니라, 채점 전용으로 독립적으로 다시 실행한다. 이는 "처치(treatment)와 측정(measurement)이 결합되면 안 된다"는 원칙을 지키기 위한 설계다.

**현재 알려진 한계**: `semantic_validator.py`의 Stage 3(관계·패턴 진단)은 병합 노드·웹훅·Code 노드에 대한 세 가지 하드코딩된 검사만 수행한다(§5.3). 즉 WIS는 "전반적인 환각/오류량"이 아니라 "이 세 가지 특정 패턴에서 발생하는 결함"만 포착하는 좁은 지표다.

### 1.4 EFR (Execution Feasibility Rate, 실행 가능률)

**무엇을 측정하는가**: 생성된 워크플로우가 실제로 동작 가능한지. `server/workflow.py`의 `/api/workflow/remote-inject`(실서비스 엔드포인트)를 그대로 호출한다.

**두 단계 판정**:
1. **웹훅 트리거 워크플로우**: 실제로 n8n에 생성 → 발행(publish) → 웹훅 호출 → 실행 기록 폴링(최대 약 28초, 점증 간격)까지 수행해 `status: success/error`를 확인한다(`execution_status`가 "executed").
2. **그 외 트리거(Manual/Schedule/앱별)**: n8n Public API가 API 키만으로 임의 트리거를 즉시 실행하는 기능을 제공하지 않으므로, 워크플로우 생성(ajv 스키마 검증 통과) 성공 여부까지만 판정한다(`execution_status`가 "schema_valid_only").

**EFR_raw vs EFR_corrected**: PCR과 마찬가지로 REG 교정 적용 전/후를 구분한다. 단, REG 교정은 노드 `parameters` 키에만 적용되며 워크플로우 구조(connections 등)는 건드리지 않는다.

**테스트 워크플로우 정리**: 모든 EFR 판정에 사용된 워크플로우는 채점 직후 n8n에서 삭제된다(실제 n8n 인스턴스를 어지럽히지 않기 위함).

### 1.5 RCR (Rule-based Correction Rate, 규칙 기반 교정 성공률)

**무엇을 측정하는가**: REG(Levenshtein 편집 거리 ≤2 기반 규칙 기반 교정기)가 무효한 파라미터명을 발견했을 때, 실제로 올바른 이름으로 교정(=편집 거리 ≤2 이내의 후보를 찾음)에 성공한 비율.

**계산 방법**: `RCR = 교정 성공 건수 / (교정 성공 건수 + 폴백 건수)`. 폴백은 무효한 이름이지만 편집 거리 2 이내에 유효한 후보가 없어 교정하지 못한 경우다.

### 1.6 통계 분석 방법

- **Wilcoxon 부호순위검정**: 연속형 지표(PCR, WIS, SA)의 Tier 간 대응표본(같은 질의, 다른 Tier) 비교. 효과크기는 rank-biserial correlation.
- **McNemar 검정**: 이분형 지표(PCR 완전정합 여부, EFR 성공/실패)의 대응표본 비교. 효과크기는 Cohen's h.
- **GEE(일반화추정방정식)**: PCR·EFR처럼 이항(0/1) 데이터를 파라미터·질의 단위로 더 세밀하게 분석할 때, 같은 질의에서 나온 관측치들의 상관(군집성)을 명시적으로 모형화한다. 계수는 log-odds, 지수변환하면 승산비(OR)가 된다.
- **선형혼합모형(LMM)**: WIS처럼 연속형 지표를 질의를 무작위 절편(random intercept)으로 포함해 분석한다.
- **Holm-Bonferroni 보정**: H1·H2·H3 세 가지 사전 등록 가설 검정에 대해 다중비교로 인한 1종 오류 팽창을 보정.
- **부트스트랩 95% 신뢰구간**: 평균 차이 추정치에 대해 10,000회 재표본으로 신뢰구간을 계산(분포 가정 없이).

## 5. 가설별 상세 결과

### H1 — PCR: Tier3가 Tier1보다 높다 → **지지됨**

- **1차 분석(GEE, 파라미터 단위, n=4,609개 파라미터)**: 계수(log-odds)=0.2727, **p<0.0001**. 승산비(OR)=**1.313**, 95% CI **[1.163, 1.483]** — Tier3의 개별 파라미터가 유효할 오즈가 Tier1 대비 약 31% 높다.
- **강건성 검정 — Wilcoxon(n=310)**: 평균 차이(Tier3−Tier1) = **+0.0257**, 95% CI [0.0046, 0.0466], **p=0.0011**(Holm 보정 후 0.0034). rank-biserial r=0.242(작은~중간 효과).
- **강건성 검정 — McNemar(완전정합 이분화, n=310)**: 완전정합(PCR=1.0) 비율 **24.2%(Tier1) → 32.9%(Tier3)**, **p=0.0053**. Cohen's h=0.193(작은~중간 효과).
- **세 방법이 모두 같은 방향(Tier3 우세)으로 일치**하며 모두 통계적으로 유의하다.

**해석**: 평균 PCR은 0.8028에서 0.8287로 2.59%p 증가하여 절대적 개선폭 자체는 제한적이었다. 그러나 파라미터 수준 GEE(OR=1.313), 질의 수준 Wilcoxon, 완전정합 여부에 대한 McNemar 검정이 모두 동일한 개선 방향을 보였으며 통계적으로 유의하였다. 특히 완전정합률은 24.2%에서 32.9%로 8.7%p 증가하였다. 따라서 H1의 결과는 대규모 평균 성능 향상보다는, 강한 GPT-4o baseline에서도 분석 단위에 걸쳐 일관되게 관찰되는 작지만 견고한 정합성 개선으로 해석하는 것이 적절하다.

#### H1 세부 분해 — PCR 개선은 H_pre와 H_post 중 어디서 오는가

Tier2(raw)의 PCR 평균은 0.8078로, Tier1(0.8028)과 Tier3(0.8287) 사이에 위치한다. 이 구간을 각각 대응표본 검정하면 개선의 출처가 명확히 갈린다.

| 구간 | 의미 | Wilcoxon p | 평균 차이(95% CI) | McNemar(완전정합) p | 완전정합률 변화 |
|---|---|---|---|---|---|
| Tier1 → Tier2(raw) | **H_pre 단독 효과** | **0.244(비유의)** | +0.0053 [-0.017, 0.027] | 0.422(비유의) | 24.2%→26.8% |
| Tier2(raw) → Tier3(final) | **H_post(REG 교정) 추가 효과** | **3.4×10⁻⁸(강하게 유의)** | +0.0209 [0.015, 0.028] | 9.5×10⁻⁷(강하게 유의) | 27.4%→33.8% |

**이 분해가 보여주는 것은 명확하다 — Tier1→Tier3 전체 구간에서 관찰된 PCR 개선은 H_pre 단독의 기여가 아니라, 거의 전적으로 H_post(REG 교정)의 기여다.** H_pre 단독(Tier2 raw)은 Tier1 대비 PCR에서 통계적으로 유의한 차이를 만들지 못했다(p=0.244). 반면 REG 교정이 적용되는 Tier2→Tier3 구간은 Wilcoxon rank-biserial r=1.0(부호 있는 차이가 전부 한 방향)일 정도로 강하고 일관된 개선을 보였다 — 이는 REG가 "존재하는 파라미터명 오류를 찾아 고친다"는 설계 목적과 정확히 일치하는, 메커니즘적으로 당연한 결과이기도 하다. 따라서 **"H_pre가 PCR 개선의 주역"이라는 서술은 이번 데이터로는 지지되지 않으며, 정확히는 "H_pre+H_post 전체 적용이 PCR을 유의하게 향상시켰고, 그중 유의한 부분은 H_post의 기여"라고 써야 한다.**

- **부가 발견 — SA는 이와 대조적으로 H_pre 단계에서 이미 거의 완성됨**: SA는 0.9636에서 0.9982로 증가하였으며(Wilcoxon p<0.0001, rank-biserial r=0.909), 본 실험에서 관찰된 지표 중 가장 큰 효과크기를 보였다. 더 중요한 것은 이 개선이 Tier2(H_pre 적용) 단계에서 이미 거의 전부 나타난다는 점이다(Tier2·Tier3의 SA 평균이 0.9982로 동일 — Tier2와 Tier3는 채점 방식만 다를 뿐 동일 생성물이므로 당연한 결과이지만, 요점은 H_pre 이후 추가로 개선할 SA 여지가 거의 남지 않았다는 것이다). 이는 H_pre가 내용 수준의 파라미터 정합성을 대폭 향상시켰다는 의미라기보다, Output Restriction을 통해 후속 시스템이 기계적으로 파싱할 수 있는 출력 형식을 안정적으로 강제하는 데 특히 효과적이었음을 의미한다 — 즉 **H_pre의 가장 강력한 실증적 기여는 구조적 통제 가능성(structural controllability)이며, PCR과 같은 내용 수준 정합성이 아니다.**

### H2 — WIS: Tier3가 Tier1보다 낮다(적다) → **지지되지 않음(방향은 일치하나 유의한 증거 없음)**

- **1차 분석(선형혼합모형, n=660 관측치)**: 계수=-0.0848, **p=0.3306**(유의하지 않음), 95% CI [-0.256, 0.086].
- **강건성 검정 — Wilcoxon(n=330)**: 평균 차이(Tier3−Tier1) = **-0.0848**(Tier3가 오히려 낮음=더 좋음), **p=0.6326**(Holm 보정 후 1.0, 유의하지 않음).
- **해석**: 방향은 가설과 일치하였으나(Tier3가 더 낮음/개선) 통계적으로 유의하지 않았으며, 본 실험에서는 WIS 감소에 대한 충분한 증거를 확인하지 못하였다. **이는 Tier 간 동등성이 입증되었다는 의미는 아니다** — 비유의(non-significant)는 "차이가 없음의 증명"이 아니라 "이번 표본에서 차이를 검출하지 못함"을 뜻한다. 또한 현재 WIS는 병합 노드·웹훅·Code 노드에 대한 세 가지 제한된 관계·패턴 규칙만을 대상으로 하므로(§1.3), 이 결과를 전반적인 의미적 오류 또는 환각 감소 여부로 일반화하지 않는다.

### H3 — EFR: Tier3(corrected)가 Tier2(raw)보다 높다 → **지지되지 않음**

- **1차 분석(GEE, n=648)**: 계수=0.0385, **p=0.3166**(유의하지 않음).
- **강건성 검정 — McNemar(n=324)**: 91.05%(Tier2) → 91.36%(Tier3), **p=1.0**, Cohen's h=0.011(거의 0).
- **부가 확인 — Tier1 대비 Tier3 직접 비교(n=292)**: 90.41%(Tier1) → 90.75%(Tier3), 역시 **p=1.0**로 유의하지 않음. 즉 이번 벤치마크에서는 EFR이 Tier 전반에 걸쳐 거의 평평하다(90~91% 수준).
- **해석**: 이러한 결과는 RCR이 11.95%로 낮아 REG가 실제로 개입할 수 있는 사례가 제한적이었던 점과, GPT-4o의 EFR이 이미 약 90% 수준이었던 점과 일관된다. **다만 본 실험만으로 H3 비지지의 원인을 이 두 요인으로 확정할 수는 없다** — 이는 사후적으로 그럴듯한 설명이며, 별도의 통제 실험(예: RCR을 인위적으로 변화시켰을 때 EFR이 어떻게 반응하는지)으로 검증된 것은 아니다.

### H4 — 개선 효과가 GPT-4o·Gemini에 공통 → **미평가**

Gemini 교차모델 벤치마크는 별도로 진행 중(아래 7절 참고).

### H5 — RCR과 파라미터명 길이가 음의 상관 → **지지됨, 매우 견고**

- **Spearman 순위상관(n=238, 질의 단위 평균 길이 근사)**: ρ=**-0.600**, **p<0.0001**(사실상 p≈10⁻²⁴).
- 파라미터명이 길수록 REG의 고정 임계값(편집 거리 ≤2) 안에서 교정에 성공할 확률이 낮아지는 경향이 뚜렷하다. §5.3의 "파라미터 길이 기반 적응적 임계값" 향후 과제에 직접적인 정량적 근거를 제공한다.
- 상관관계이며 인과관계를 주장하지 않는다.

## 6. 1차 결과(모델 버그 있던 버전)와의 비교 — 왜 이 재실행이 중요했는가

| 항목 | 1차(결함, Tier2/3=GPT-4o-mini) | **2차(수정, Tier2/3=GPT-4o)** | 변화 |
|---|---|---|---|
| PCR 평균 차이 | +0.073 (p<0.0001) | **+0.026 (p=0.0011)** | 효과 축소, 유의성 유지 |
| 완전정합률 | 24.0%→39.7% (거의 2배) | **24.2%→32.9%** | 효과 축소, 유의성 유지 |
| GEE 승산비 | 1.556 [1.35,1.79] | **1.313 [1.16,1.48]** | 효과 축소 |
| WIS | 0.112→0.252(악화), **p=0.021 유의** | **0.273→0.188(개선), p=0.633 비유의** | **결과 자체가 뒤집힘** |
| EFR Tier1→Tier2 | 88.9%→98.4%(9.5%p) | **90.6%→91.0%(0.4%p)** | 거의 소멸 |
| H3 | p=1.0(비유의) | p=1.0(비유의) | 동일 |
| H5 | ρ=-0.584 | ρ=-0.600 | 거의 동일(견고) |

**핵심 시사점**: 1차 실행은 Tier 간 모델 조건이 일치하지 않아(Tier1=GPT-4o, Tier2/3=GPT-4o-mini) Harness 효과와 모델 차이가 교락(confounded)되어 있으므로, 확인적(confirmatory) 분석에서 제외하였다. 동일 GPT-4o로 통제한 재실행(본 문서)에서는 1차 실행에서 관찰된 WIS의 유의한 역방향 차이와 큰 EFR 차이가 재현되지 않았으며, PCR 개선은 효과 크기가 축소되었으나 통계적으로 유의한 상태로 유지되었다. 따라서 본 연구의 최종 추론은 수정 후 재실행 결과만을 기반으로 한다.

PCR 개선은 동일 모델 조건에서도 관찰되었으며(다만 5절 세부 분해에서 확인했듯 그 출처는 H_post에 집중된다), RCR과 파라미터명 길이 간 음의 상관은 두 실행에서 유사한 크기로 반복 관찰되었다.

## 9. 종합 해석

본 실험은 Comprehensive Harness의 모든 계층이 모든 품질 지표를 일률적으로 향상시키는 결과를 보이지 않았다. 대신 각 계층과 평가 차원에 따라 효과가 상이하게 나타났다.

H_pre 적용은 특히 구조 정합도(SA)를 0.9636에서 0.9982로 향상시켜, 출력 형식을 기계적으로 처리 가능한 구조로 제한하는 데 강한 효과를 보였다(rank-biserial r=0.909). 반면 H_pre 단독은 파라미터 정합률(PCR)에서 Tier1 대비 통계적으로 유의한 차이를 만들지 못했다(Tier1→Tier2 Wilcoxon p=0.244). H_pre와 H_post를 포함한 최종 Tier3에서는 PCR이 0.8028에서 0.8287로 증가하였으며, GEE·Wilcoxon·McNemar 분석 모두에서 유의한 개선이 확인되었다 — 그러나 5절의 세부 분해에 따르면 이 개선은 거의 전적으로 Tier2→Tier3 구간, 즉 H_post(REG 교정)의 기여다(Wilcoxon p=3.4×10⁻⁸). 평균 PCR의 절대 개선폭은 2.59%p로 제한적이었으나, 완전정합률은 24.2%에서 32.9%로 8.7%p 증가하였다.

반면 WIS에서는 가설 방향의 감소가 관찰되었으나 통계적으로 유의하지 않았으며, H_post 적용에 따른 EFR의 추가 개선도 확인되지 않았다. 따라서 본 결과는 Harness의 효과를 전반적인 성능 향상으로 일반화하기보다, **구조적 출력 통제(SA)는 H_pre 단계에서, 파라미터 수준 정합성(PCR)은 H_post 단계에서 각각 실증적인 개선이 확인되었으며, 사후 규칙 기반 검증의 실행 가능성 개선 효과(H3)는 이번 벤치마크에서 확인되지 않았다**고 해석하는 것이 적절하다.

이러한 결과는 H_pre, H_post, H_exec를 동일한 "성능 향상" 계층으로 뭉뚱그리기보다, 각각 **사전 생성 통제(Prevent/Ground — 온톨로지·RAG로 근거를 주입하고 출력 형식을 강제), 사후 교정·진단(Correct/Diagnose — 이미 생성된 결과에서 알려진 오류 패턴을 찾아 고치거나 알림), 실행 검증(Verify — 정적 분석으로는 확인할 수 없는 실행 단계의 성패를 관찰)**이라는 서로 다른 역할을 수행하는 구성요소로 구분해 해석할 필요성을 보여준다. 특히 H_exec는 생성 정확도를 직접 향상시키는 계층이 아니라, 이미 확정된 산출물의 실행 성패만을 사후적으로 관찰하는 검증 계층이라는 점에서 다른 두 계층과 성격이 다르다(§3.1의 Generation Control vs Runtime Verification 구분과 일치).

**환각(hallucination)에 대한 결론 유보**: PCR은 "존재하지 않는 파라미터명을 생성하는 것"과 같은 구조적 부정확성을 결정론적으로 포착한다. 이는 환각의 한 형태이지만, 근거 없는 능력 창작형 환각 전반(§4.6의 HR이 다루는 범주)을 포괄하지 않는다. 따라서 이번 결과로부터 "Harness가 환각을 유의하게 감소시켰다"는 결론은 아직 내리지 않는다 — 이는 HR 측정(근거 대조 기반 라벨링, 별도 웹 도구로 예정)이 이루어진 뒤에 판단할 사안이다.
