# Part A — 성향 진단 문항 (v2.0)

> **언제 묻는가**: 최초 온보딩 때 **딱 한 번**. 이후에는 재진단(설정에서 "성향 다시 진단하기")을 하지 않는 한 값이 바뀌지 않는다.
> **무엇을 만드는가**: 사교성·취향모험도·가치관·계획성 4개 축의 연속 점수 → `user_travel_persona` 테이블 → 16개 유형 코드.
> **문항 수**: 40문항 (축당 10문항, 5점 리커트). 이전 버전(28문항) 대비 축당 3문항씩 늘려 신뢰도를 높였다.
> 다른 파트: [Part B — 여행 취향 프로필](02-questionnaire-b-profile.md) · [Part C — 이번 여행 정보](03-questionnaire-c-trip.md) · [전체 개요](00-overview.md)

## 0. 응답 방식

| ① | ② | ③ | ④ | ⑤ |
|---|---|---|---|---|
| 전혀 아니다 | 아니다 | 보통이다 | 그렇다 | 매우 그렇다 |

문항은 **성격 → 여행 스타일 → 음식 스타일 → 숙소 스타일** 4개 섹션에 걸쳐 배치했다. 사용자에게는 "다양한 각도로 물어보는 테스트"로 느껴지고, 내부적으로는 같은 축을 여러 생활 맥락에서 교차 검증한다. `방향`이 `역`인 문항은 채점 시 `6 - 응답값`으로 뒤집는다.

## 5. 채점 방법

### 5.1 문항 정규화

```
정채점: normalized = (응답값 - 1) / 4      # 1~5 → 0~1
역채점: normalized = (5 - 응답값) / 4      # 1~5 → 0~1 (뒤집힘)
```

### 5.2 축 점수 (각 축 10문항 평균)

```
social_score      = mean(A1, A2, A3, A4, A5, B1, B2, D1, D2, D3)
adventure_score   = mean(A6, A7, B3, B4, B5, C1, C2, C3, C4, C5)
experience_score  = mean(B6, B7, C6, C7, C8, C9, D4, D5, D6, D7)
flow_score        = mean(A8, A9, A10, A11, A12, B8, B9, B10, B11, B12)
```

### 5.3 유형 코드 생성

```
letter1 = 'S' if social_score     >= 0.5 else 'P'
letter2 = 'A' if adventure_score  >= 0.5 else 'C'
letter3 = 'E' if experience_score >= 0.5 else 'V'
letter4 = 'F' if flow_score       >= 0.5 else 'J'
persona_code = letter1 + letter2 + letter3 + letter4
```

`persona_code`로 [00-overview.md](00-overview.md) 4절 표를 조회해 유형명과 [types/](types) 파일을 사용자에게 보여준다. 경계값(0.45~0.55) 처리, `survey_version` 관리 원칙은 이전과 동일하다 — 상세는 [00-overview.md](00-overview.md) 5·7절 참고.

## 6. 구현 메모

- 문항 ID(A1, B3 등)는 고정 키로 취급한다. 카피라이팅(문구 다듬기)은 자유롭게 하되, ID·축·방향 매핑표는 변경하지 않는다. 매핑 자체를 바꿔야 한다면 `survey_version`을 올린다.
- 40문항은 한 화면에 다 보여주지 않고, 섹션(성격/여행/음식/숙소) 단위로 4개 화면에 나눠 진행률 바와 함께 보여주는 걸 권장한다.
- Part A는 [Part B](02-questionnaire-b-profile.md)와 같은 온보딩 흐름 안에 있지만 성격이 다르다 — Part A는 "채점되는" 문항, Part B는 "그대로 저장되는" 문항이므로 사용자에게도 "간단 성향 테스트"와 "여행 취향 설정"처럼 다른 톤으로 구분해 안내하는 게 좋다.
